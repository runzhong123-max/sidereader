# 知识图谱布局升级记录

目标：让学生先看懂核心与扩展，再按需要查看先修层次、交叉关系和概念详情。点、名称、连线必须保持明确对应。

## 基线与证据

- 2026-09-28 用户截图与 Safari 实机：第三章 20 个概念、18 条关系，缩放 15%；圆点挤在中央，文字被引线推到四周，大量画布空置。
- `graph-layout.mjs` 使用力导向排列圆点，之后 `placeGraphLabels` 独立搬动屏幕标签；避开文字重叠却破坏了名称与节点的邻近关系。
- `Graph.tsx` 缩放保持文字字号，窗口调整只平移镜头；历史固定节点参与所有自动布局。旧测试只证明无重叠，不能证明容易理解。
- `server/graph-generation.mjs` 明确规定 `links` 为本概念依赖的先修 ID。当前渲染把关系无向去重；数据没有“教学核心”的可靠标记。

## 假设与设计实验

- 核心展示起点可以由先修拓扑推导，但不能把连接多的概念宣称为教材重点；用户应能改换展开起点。
- 比较三种布局：核心展开（看主干分支）、分层关系（看依赖方向）、自由网络（看交叉关系）。同一数据切换，仅改变位置与显示范围。
- 标签与节点使用固定相对位置，按完整文字尺寸排列节点。收合仅过滤既定位置，缩放不重排标签。
- 大图先展示主干并明确未展开数量；可逐层或全部展开，搜索必须能找到未展开概念。小屏允许平移，不以挤压所有名称作为成功标准。

## 研究依据

- [Novak 与 Cañas，概念图理论](https://cmap.ihmc.us/docs/theory-of-concept-maps)：概念层次与跨分支联系有助于组织知识；核心取决于所回答的问题。应用：提供展开起点与交叉关系，而非声称自动推导出唯一学习顺序。
- [yWorks Radial Layout](https://docs.yworks.com/yfiles-html/dguide/layout/radial_layout.html)：以树组织层级后保留非树边，布局考虑标签尺寸。应用：节点和文字共同占位；不丢弃交叉边。
- [yWorks Incremental Diagram Layout](https://www.yworks.com/pages/incremental-diagram-layout)：局部变化应尽量保留已有位置以保持方向感。应用：展开/收合不重新计算坐标。
- Exa 后端本机不可用，研究使用可用 Web 搜索读取上述原始资料。

## 验收约束

- 正确性：先修方向、循环、多根、断开部分、全部概念可达；布局不改写知识数据。
- 几何：文字紧贴所属圆点；自动布局无文字互压；适应窗口考虑点与完整文字；边不以标签引线混淆关系。
- 操作：三模式可发现；逐层/全部/以此展开；缩放围绕指针、平移、返回全图、详情与拖拽引用；布局切换与用户缩放不相互打架。
- 环境：真实 Safari；章节图、对话卡片、浮窗/并排/主视觉、亮暗、小窗、大图。
- 对照：同样内容的旧算法与新布局，不能只依据实现者自述；记录测试、独立审查及修复。

## 实验中的失败路线与修复

- 相对放大局部距离导致反复选点越拉越散：改为44世界单位绝对空隙，已有空隙足够就不动；30次往返复验稳定。
- 选取已移动的邻居时从旧全局坐标重新开始：改为从当前显示位置取快照，焦点不跳回旧处。
- 拖动覆盖在布局之后叠加造成新重叠：覆盖仅限手势期间，成功松手转为基础布局输入，取消或拖出恢复。
- 来源筛选忽略折叠分支、返回全图仍只显示主干、收起后整图变灰：独立审查复现后逐项修复，生产组件事件测试纳入回归。
- 图谱关闭期间改名后重开恢复旧几何：缓存签名包含ID、名称、关系与持久化坐标，只有签名匹配才恢复快照。
- 初始局部镜头可能因随机ID选中小的独立部分：优先覆盖较多可见节点的起点，不把ID排序当作重要性。
- Safari热更新时曾出现计算样式和源样式不一致；完整重新载入后复核，亮暗主题与即时淡化正确。没有把这次现象归因于已证明的Safari产品缺陷。

## 保留取舍与待验证

1. 自由网络手动拖动松手后，其他未固定节点会重新参与力布局；只有“局部舒展”保证焦点与外围固定。手动固定位置互相冲突时保留用户位置，不承诺消除所有重叠。
2. 小窗优先可读字号，部分概念需要平移、缩略导航或搜索；“适应窗口”主动看全貌时允许文字变小。主干收合保留完整布局坐标，避免反复展开位置洗牌，因此可能留有空隙。
3. 100节点330边的额外密集实验首次布局及避字路由约1.38秒；平移缩放复用路由。更大规模还需要性能测量。
4. 当前证据证明几何、状态和已执行操作的改善；还没有学生长期学习效果的数据。
5. 未完成的Safari场景：原生平移/滚轮/拖出引用、连续鼠标换焦点、对话卡片中的真实拖动、拖动触发的跨视图恢复。通过菜单切换视图的状态恢复已在下方补验；原生手势待窗口接口恢复后继续，不降低验收标准。

## 手势取消与键盘复验（2026-09-28）

独立审查发现四个可具体复现的问题，本轮逐项修复：

- 菜单项执行后，焦点可能落回页面：菜单关闭并完成渲染后恢复触发按钮；如果新编辑器已经接管焦点，则保留新焦点。Safari 实际键盘切换“自由网络”后，确认焦点回到布局按钮。

- 窗口失焦或标签隐藏时，未完成的拖动仍可能留在进行中：统一取消并恢复原位置，释放捕获、清理引用落点；晚到的松手不能重新保存或引用。
- 拖动期间滚轮会改变坐标比例，松手还可能漏掉最后一段位移：手势期间忽略滚轮；正常松手消费最终坐标，取消时不消费。
