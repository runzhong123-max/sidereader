# SideReader：双模式与有界 Agentic RAG

## 这次修复的问题

旧流程只有一次查询扩展，最终截取6个片段。给每个来源补一个开头片段并不能支撑整本书规划。新流程把项目结构索引、问题研究和阅读锚点分开处理，但使用同一套证据、引用与持久化对象。

## 设计依据

- [PageIndex](https://github.com/VectifyAI/PageIndex)：文档目录导航与可追溯阅读。借鉴结构视图；本项目先用确定性章节识别/文档路径，没有搬入其模型索引依赖，也不引用其性能作为我们的效果。
- [Open Deep Research](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/deep_researcher.py)：工具结果反馈、研究迭代预算、收束综合。借鉴循环与停止条件；这里使用单Agent，不为相同资料部署多Agent讨论。
- [LightRAG](https://github.com/HKUDS/LightRAG)：局部和全局视角、增量对象维护。这里的知识图谱是教学对象，尚未作为图数据库检索索引；不可把它称为完整LightRAG实现。
- [Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)：片段需要来源上下文，词法与语义互补。当前保留标题、路径、物理页、章节范围；没有实现逐块LLM上下文化或独立reranker。

2026-09-23 通过 Agent Reach 的 Exa 与 GitHub CLI 阅读以上官方资料，未复制执行第三方项目代码。

## 实际工作流

1. 从全部已导入chunk建立来源→章节/文档目录，忽略目录页里的伪章节和重复页眉。无法提取章节时用16页段降级。缓存键包含正文，来源变更自动失效，最多4份内存缓存。
2. 规划从每个目录项的代表片段起步，超过24项时均匀抽样并如实显示缺口。Agent根据这些结果选择检索词、章节或连续物理页，下一轮能看到真实新增证据和工具失败反馈。仅初始抽样不能通过深度研究完成检查。
3. 阅读先固定当前页和相邻页证据，不被全库排序挤掉；选区和可见文字独立注入，发送时截取当前位置。引用跳转在阅读容器中对齐原文，避免标题居中导致上一页被当作当前页。
4. 综合带完整证据编号、抽读覆盖、未解决缺口与停止原因。证据至多40块×1800字符；达到容量时报告未装载的候选，不伪装已读。
5. 需要学习规划/图谱/关卡时载入专门维护skill。综合可提交 maintain_graph / maintain_path 参数，运行时检查真实证据引用、有效ID和无环关卡依赖。前端显示提案；应用以最新项目状态增量合并，保留done与布局，不删除未提及对象。

工具采用OpenAI兼容JSON调度协议，执行器是代码白名单；不是原生function-calling，也不运行生成的代码。维护工具是独立校验函数，外部资料无法通过工具执行命令。每个关卡有产物、验收、先修和原文锚点，可直接进入阅读。书签同样持久化在项目IndexedDB中。

## 成本与可观测性

- 普通问答最多3次模型调用；深度研究最多4次，单请求最多240秒。没有隐藏重试或无界子代理。
- 全库索引零模型调用；可选Embedding限制96候选，避免首次问题隐式重建全库向量。
- 记录供应商实际输入/输出token、调用次数、耗时、工具轨迹和索引/抽读覆盖。未返回usage时不推算为零费用。
- 不记录密钥；报告跟随消息保存在本机。没有跨问题缓存最终回答，避免过期目标、作答或阅读位置污染答案。

## 验证与边界

Safari实机使用《机器学习》完成3轮研究、4次模型调用：建立17个目录项（开篇+16章），抽读34个物理页，生成16个概念、7个带阅读锚点的关卡。该次报告耗时17.6秒，输入64,271、输出3,118 tokens；这是单次观测，不是质量或延迟基准。提案已应用到机器学习项目。达到证据预算的未读细节仍明确标注，不声称完整精读。

自动回归覆盖多轮补读反馈、禁止仅凭抽样结束、阅读锚点保留、空/重复工具结果、取消、目录缓存失效、Embedding候选上限、引用校验、关卡无环、增量合并幂等及完成记录保留。HTTP集成覆盖逐行进度与完整结果。Safari用于实际页面交互验收。

当前深度研究仅面向已导入资料。扫描OCR错误、GitHub只导入部分文档、自动章节识别错误会限制结论；模型仍可能给出不恰当的教学先修或验收，需要查看原文与提案。知识图谱尚未参与检索，多书跨学科规划也未建立量化评测集。下一步应先积累典型题的证据召回与规划质量评测，再按失败样例决定是否增加持久向量索引、reranker或章节摘要。
