# SideReader：功能、对象与交互审查

日期：2026-09-23。依据是用户提供的两份产品哲学材料，以及本项目代码与使用流程。下表中的公司名称标识材料提供的设计视角，不把文章的概括当作各公司的官方定义，也不据此复制其全部产品形态。

状态说明：“通过”限于所列契约；“已修复”指实现已落地，具体自动与 Safari 验证证据见末节；“部分”不计为全面达标。

## 1. 主线与取舍

**SideReader 帮助计算机专业学习者，沿着自己的目标，把原文转化为理解、实践和可检验的成果。**

完整过程：导入资料 → 研究与规划 → 阅读和追问 → 练习或实践 → 根据证据调整规划。

- 用户决定目标、材料、当前问题、是否采用成果、何时停止。
- 系统负责解析与索引、关联阅读上下文、按需检索、组织教学、保持对象和进度一致。
- 两个主要入口是“新对话”和“阅读”。图谱、关卡和题目是成果，不增加同级的产品模式。
- “讲解／引导／自测”是可组合的内部策略。用户可自然提出“直接讲清楚”“先给提示”“考考我”，无需先选择模式；一次请求不锁定后续对话。

## 2. 功能：用户要完成什么

功能是动作或能力，不是需要在左侧逐项列出的页面。

| 功能               | 输入 → 结果                           | 合格条件                                     | 审查及修复                                                                                             |
| ------------------ | ------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 管理项目           | 目标、材料 → 持久项目                 | 现有投入不被初始化覆盖                       | **原不合格，已修复**：读取错误不再进入自动保存；未知存储格式保留原数据；旧版个人数据优先于示例         |
| 导入 PDF／GitHub   | 文件／URL → 原文、文本与索引          | 操作承诺真实，可停止，成功即入库             | **原不合格，已修复**：不再“处理并添加”后还需第二次加入；处理有取消路径。PDF 未完成任务的恢复范围见末节 |
| 总体研究和规划     | 目标＋项目材料 → 有依据的说明与提案   | 先了解目录、覆盖，再多轮补证据；声明缺口     | **部分合格**：已有有界 agentic RAG、目录缓存、查询与章节工具；广泛学科与长书质量不能由机制测试证明     |
| 常规问答           | 当前问题＋历史 → 清楚、有据的回答     | 当前意图优先，必要时补检索                   | **机制通过**：内置教学策略，无前置模式选择；保留回答渲染和引用                                         |
| 阅读辅导           | 材料、页码、可见正文、选区 → 局部理解 | 翻页即更新上下文，证据不足再检索             | **机制通过**：连续 PDF、当前阅读上下文、引用定位；不以“看过”推断“学会”                                 |
| 管理图谱           | 概念和关系 → 可浏览、可编辑网络       | 有稳定 ID、能回原文、修改不重置整个图        | **基本通过**：力导向布局、局部邻域、搜索、缩放、拖动固定、节点及连接编辑；关系语义仍较简单             |
| 管理关卡           | 目标和研究 → 任务、产物、验收、先修   | 展示的关键字段可编辑，删除不留坏引用         | **原不合格，已修复**：完整编辑；阻止手动循环先修；删除清理引用并可撤销，保留后续修改                   |
| 作答与反馈         | 题目＋用户答案 → 作答记录、反馈       | 提交才计分；自评与客观判断分开；结果入上下文 | **原不合格，已修复**：跨视图草稿与提交同步；题目修订后旧成绩不冒充新成绩；去掉“本次掌握”结论           |
| 打开成果／分支追问 | 回答对象 → 纸张及子对话               | 不复制身份；来源、父子关系可返回             | **原部分合格，已修复题目一致性**：重复打开保留纸张和对话；文件题目按当前内容解析                       |
| 中止和恢复         | 研究／导入／保存错误 → 明确下一步     | 用户能停止，失败不伪装成功                   | **原不合格，已修复**：研究按会话保存运行态，防重复启动；本机保存失败常驻反馈与重试                     |

## 3. 对象：哪些成果需要身份与生命周期

对象至少有稳定身份、明确归属、可打开的内容及来源语义。“界面上的一块内容”不自动等于一个新的数据库对象。

| 对象               | 归属与职责                                 | 可进行的操作                               | 对照结论                                                 |
| ------------------ | ------------------------------------------ | ------------------------------------------ | -------------------------------------------------------- |
| 项目               | 总容器，保存目标和全部工作                 | 新建、切换、改名、改目标、删除             | 通过；新增失败保护，不将“本机存储”误称备份               |
| 知识来源           | PDF、GitHub 文档及索引                     | 导入、打开、移除                           | 部分：已有导入和定位，尚无完整增量版本管理               |
| 阅读锚点／书签     | sourceId＋页码＋可选引文                   | 收藏、取消、定位                           | 通过；来源消失时提示，保留引用历史                       |
| 对话               | 消息序列及当前输入                         | 继续、关闭标签、重开、停止研究             | 修复：草稿与运行状态不再属于某次组件挂载                 |
| 概念／知识图谱     | 概念 ID、说明、连线、来源、布局            | 编辑、连接、搜索、拖动、回原文             | 基本通过；单个节点关联不是“已掌握”证据                   |
| 关卡／学习路径     | 任务、产物、验收、先修、阅读入口、完成状态 | 完整编辑、完成、删除、撤销最近删除         | 修复：字段可维护；完成状态由用户标记，撤销不覆盖后续进度 |
| 题目文件           | 有序题目集合                               | 建立、编辑、练习、打开题目纸张             | 修复：位置和未提交答案持久化，与纸张共用状态             |
| 题目               | 选择／判断／简答，稳定对象 ID 和内容版本   | 就地作答、查看提示、提交、自评、再练、打开 | 修复：相同题目多视图一致；编辑题目产生新版本语义         |
| 作答记录           | 不可变的当次表现及题目版本                 | 回看反馈、带入 tutor 上下文                | 修复：只统计已提交；简答自评与客观题分开，提示辅助可见   |
| 代码／伪代码       | 学习材料与语言标记                         | 渲染、复制、展开到纸张、追问               | 当前是材料对象；不宣称代码已执行或测试通过               |
| ASCII 图／表／公式 | 结构、比较、推导的表达                     | 等宽／表格／数学渲染、打开、追问           | 通过展示契约；不是任意可视化编辑器                       |
| 图对象             | 受约束的折线／散点／柱形数据               | 图形展示、打开、追问                       | 部分：当前是受约束图表，不是任意 matplotlib 脚本执行器   |
| 执行轨迹／概念卡   | 算法步骤、变量变化、关键定义               | 逐步阅读、打开、追问                       | 通过当前范围；适合计算机阅读，不必再增加顶层入口         |
| 来源摘录／工具结果 | 本次引用、检索结果的可追溯材料             | 打开、查看原文、继续提问                   | 通过；使用当次证据快照，不能混成最新原文                 |
| 笔记／追问纸张     | 对象内容及独立对话，保留父节点             | 打开、返回上级、在树中定位                 | 通过；关闭标签不删除纸张                                 |
| 研究报告／更新提案 | 覆盖、证据、步骤、待采用图谱或关卡变更     | 看依据、采用、打开结果、撤回               | 通过事务机制；历史未记录 before 状态的提案不可追溯撤回   |

**同一对象与快照的边界：**题目文件是可编辑原对象，其纸张显示当前题目；旧作答保留原题干和判断。回答里的工具结果、证据和生成代码则属于当次回答的快照；重新研究不悄悄改写历史。源题删除后，已有纸张可保留当时快照以支持回看。

暂不继续细分“调试、复杂度、实验”等顶层类型：先用现有代码、执行轨迹、表、图及关卡的产物/验收组合表达。只有出现不能准确存储或操作的需求，才新增对象契约。

## 5. 修复的实现边界

- `src/project-loading.mjs`：已有存储优先；读取错误/未知格式拒绝继续初始化。`App.tsx` 仅成功加载后自动保存，并提供读取、保存重试。
- `src/stage-state.mjs`：先修检查、删除收据、撤销；保留后来编辑的先修、完成记录，不重建已删除的其他关卡。
- `src/question-state.mjs`、`paper-state.mjs`：题目版本、草稿、已提交表现、纸张解析；UI 在同一对象状态上工作。
- `src/tutor-sessions.mjs`：按会话管理草稿与运行状态。
- 导入处理：请求取消传递到服务端与提供方；成功触发实际加入，而不是只显示临时成功页面。

## 6. 尚不能宣称达标的部分

1. **研究的学术与教学质量**：有界多轮检索、引用和覆盖审计已经实现，但并不证明每个规划正确、每条知识关系有用。继续按真实教材任务做评估；不要用 UI 完成度替代质量评估。
2. **长期任务恢复**：切换 SideReader 内部标签可继续控制研究；浏览器刷新或服务重启后的研究续跑不是已实现的持久任务系统。
3. **导入的恢复范围**：恢复已完成 PDF 页限定在当前未关闭的导入任务；尚非跨浏览器重启的导入任务队列。明确停止与关闭的区别。
4. **存储范围**：目前是本机浏览器数据；读写失败保护和重试不等于跨设备同步、备份、跨 Safari 标签并发冲突处理。
5. **通用编辑与执行**：代码和复杂图形是可阅读、可追问的材料；尚无安全代码执行器、任意图表编辑器或全对象版本历史。
6. **手动删除的恢复覆盖**：本轮为关卡补上持久撤销；图谱节点、单题和题目文件的手动删除尚没有统一回收站，本轮补上明确后果的删除确认，避免误触直接丢失。AI 提案撤回已有字段级恢复，但不等于所有删除操作都可恢复。
7. **无障碍验收**：原生按钮、对话框、标签、提示已有语义，但不能因此声称已完成完整键盘、VoiceOver 与对比度合规审计。

以上是产品边界或需要持续证据的质量项，不通过增加模式、强制设置或空入口来掩盖。
