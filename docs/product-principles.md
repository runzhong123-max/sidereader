# SideReader 的产品、功能与界面取舍

依据：用户确认的阅读、纸张和对象规则。产品结构以 [六条准则](../DESIGN.md#六条准则) 为准；早期设计研究只作为历史依据。

## 产品承诺

帮助学生读懂 PDF 教材，能随时追问、核对、整理概念并用少量练习检验理解。

核心流程：找到章节 → 阅读与追问 → 按需看图、做题 → 回到原文继续。

一个项目一本 PDF；左侧保留章节导航，默认中央阅读、右侧对话。项目和章节可挂多个主对话，主对话内部才展开追问纸张树。图谱与习题是卡片，同样可以成为主视觉、并排内容或浮窗。放置方式不改变内容归属。

## 用户决定什么，系统承担什么

| 用户保留的决定                                     | 系统承担的复杂性                         | 必要的可见反馈                     |
| -------------------------------------------------- | ---------------------------------------- | ---------------------------------- |
| 学什么、希望做出什么、已有基础                     | 根据目标研究资料，形成可行起点           | 下一步行动及采用它的理由           |
| 使用哪些材料、当前关注哪段内容                     | 解析、索引、定位、补充检索               | 原文位置、依据与实际覆盖范围       |
| 当前想解决的问题，以及是否需要提示、练习或完整答案 | 根据当前请求和已有尝试选择、组合教学策略 | 直接回应需求，不要求先选择辅导模式 |
| 是否采用、如何修改生成成果                         | 生成并合并结构化对象、维护引用           | 新增或修改了什么，以及恢复入口     |
| 何时停止或调整研究                                 | 控制轮次、证据预算和重复检索             | 当前行动、停止控制、失败原因       |

检索轮数、分块参数、向量召回比例等不进入日常学习界面。自动化承担流程负担，但不能替用户宣称已经掌握知识，或把抽样覆盖说成整本精读。

## 功能边界

优先完善一条可直接使用的学习流程。扩展能力通过现有对象与侧面展开入口进入，不持续增加顶层导航。

- 图谱表达有依据的概念关系；关卡表达下一步任务、产物与验收，两者各有用途。
- 代码、伪代码、ASCII 图、图表、表格和公式是可操作的学习材料；统一打开、引用与追问行为。
- 题目可以就地作答，也可打开独立卡片；作答记录影响后续辅导，但完成不等于掌握。
- 纸张树记录对话的追问关系；图谱与习题保留来源、范围与统一身份，只在主动追问时显露自己的对话。
- 暂不扩展通用页面搭建器、工作流编排器、社交或推荐信息流。这些需求出现时重新按核心流程判断。

## 界面规则

1. **内容优先且可读。** 原文、回答或当前对象占据主区域；不能用低对比、小字号换取视觉上的轻量。
2. **稳定入口，统一行为。** 左侧是项目、章节与主对话；子对话留在内部纸张树，对象用卡片呈现。来源引用先预览摘录，明确打开后才定位原文；保留正在使用的内容。
3. **默认能开始。** 提问时自动决定是否需要深入检索；用户仍可显式要求深度研究。首次使用不先填写研究参数。
4. **过程分层。** 正在执行的动作与停止入口可见；完整工具轨迹、预算、token 等在详情中查看。过程完成后让回答重新成为主角。
5. **成果可控。** 采用前能看懂变更；采用后能继续编辑，并应支持恢复。避免只能重新生成整份成果。
6. **减少重复操作。** 看过的位置、已答过的题、已生成的对象由系统记录；让用户重新描述上下文之前，先检查已有记录。
7. **可恢复比反复确认更有效。** 对可逆操作优先提供清晰反馈和撤销；危险或不可恢复操作再单独处理。
8. **控制须有真实的用户决定。** 不把内部教学策略直接做成模式选择。正常问题直接回答，用户说“给提示”“考考我”时按当前意图调整；不延续一次性的教学模式。研究深度影响时间和覆盖范围，可按需控制。应用或撤回后，在结果旁提供对应对象入口，避免重新寻找。
9. **保持已有投入。** 保留资料、作答、阅读位置、布局和对象引用；进阶能力通过情境控制进入。切换主视觉、并排和浮窗只更换呈现位置。

## 实现与验收

当前交互和验证记录见 [纸张与拖拽](paper-tree-design.md)，统一身份、归属和模块边界见 [架构](../ARCHITECTURE.md)。历史提案没有变更前快照时不能追溯撤回，仍可编辑；不伪造恢复能力。

## 每次改动的验收问题

- 用户为了继续学习，是否少做了一次重复选择或说明？
- 当前主任务是否更显眼，同时仍能找到必要控制？
- 系统做出判断时，用户是否知道依据并能纠正？
- 出错后能否回到之前状态，且不会丢掉后续工作？
- 在真实 Safari 的原文阅读、追问、打开成果、返回原文流程中是否成立？

一个改动若只是增加按钮或面板，没有改善这些问题，不因功能看起来完整就优先加入。
